## Purpose

Preserve a small number of **earned failure shapes** so a future Framework aperture can retrieve the right lesson when the same causal pattern returns in different subject matter.

This file is not part of default boot cognition. It is a cold retrieval surface behind the omission map.

```text
LESSON_STORED != LESSON_AVAILABLE_AT_DECISION
TOPIC_MATCH != STRUCTURAL_MATCH
SCAR_MATCH != DIAGNOSIS
RETRIEVAL != APPLICATION
PAST_FAILURE != CURRENT_CAUSE
REMEMBERED_CAUTION != AUTHORITY
```

A scar is a **warning hypothesis**. When the present situation resembles one:

1. retrieve the named evidence rather than relying on this compression alone;
2. test whether the current causal structure really matches, not merely the vocabulary;
3. check current owners, evidence, authority and consequences;
4. adapt, reject or retain the old lesson;
5. do not apply the old cure automatically.

Do not add a scar because a pattern is theoretically attractive. Add one only after a real project failure, adverse/null consequence, hostile attack or repeated correction earns it and leaves a named evidence route.

## S1 — PURPOSE-SHRINK SCAR

### Failure shape

```text
stronger external owner found
-> local claim narrowed / deleted
-> same operation repeated
-> project purpose quietly contracts toward residual novelty
```

### Lesson

Cut overclaims and weak instruments without silently redefining the whole project as "whatever nobody else already does."

`DOMAIN_OWNER_BETTER -> USE_DOMAIN_OWNER` can be true while `PROJECT_PURPOSE != RESIDUAL_NOVELTY` remains true.

### Earned by / retrieve

- COM #74 comment `5532139651` — current structural-scar synthesis.
- COM #74 Open Horizon body — anti-closure and `KNOWN_IN_ANOTHER_DISCIPLINE != ALREADY_INTEGRATED`.
- COM #76 currentness / post-falsification history — repeated owner-subtraction cycles and later correction.

### Does not mean

- every local mechanism should survive;
- TRACE/ME must expand;
- overlap with stronger owners is evidence of value;
- a project purpose can never legitimately narrow.

### Reopen / disconfirm if

Repeated real-world use shows that the broader project inquiry itself produces no consequential integration, activation, learning or human benefit beyond lower-burden owner-native methods.

## S2 — CATALOGUE SCAR

### Failure shape

```text
uncertainty / open horizon
-> search
-> classify
-> name / number
-> post / count
-> visible artefact growth substitutes for understanding the relation
```

### Lesson

Naming is not discovery. Think longer about the relation before promoting it into a durable object.

### Earned by / retrieve

- COM #74 comment `5532139651` — catalogue-machine scar.
- COM #74 current Open Horizon history — frontier expansion followed by mirror correction.

### Does not mean

- names, taxonomies or indexes are always bad;
- discoverability should be sacrificed;
- a genuinely distinct frontier should remain unnamed forever.

### Reopen / disconfirm if

A named object repeatedly improves retrieval, coordination or consequential action at lower burden than leaving the relation implicit.

## S3 — INFRASTRUCTURE-THEATRE SCAR

### Failure shape

```text
continuity / currentness burden noticed
-> build mechanism
-> validate mechanism
-> mechanism becomes the work
-> human burden / world consequence remains unmeasured
```

### Lesson

Continuity infrastructure is justified by reduced human/currentness burden and better action, not by internal contract strength alone.

### Earned by / retrieve

### Does not mean

- validation is useless;
- local tools such as Steward have no value.

### Reopen / disconfirm if

A concrete mechanism measurably removes transport/retrieval burden, catches a real currentness failure, or enables a consequential action that competent ordinary practice could not achieve at equal or lower burden.

## S4 — AUTHORITY-TYPE-ERROR SCAR

### Failure shape

```text
latency / bottleneck / single point observed
-> treat authority as fungible capacity
-> propose redundancy by expanding mandate
```

### Lesson

A shortage of speed or redundancy is not automatically an authority defect. Do not manufacture alternate authorizers merely because legitimate authorization is a bottleneck.

```text
AUTHORIZATION_LATENCY != AUTHORITY_DEFECT
SINGLE_LEGITIMATE_AUTHORITY != REDUNDANCY_FAILURE
CAPABILITY != AUTHORITY
```

### Earned by / retrieve

- COM PR #101 discussion — shared-capacity stress test authority repair.
- COM #76 current PR #101 review-basis / authority-ceiling receipts.

### Does not mean

- authority topology is always legitimate;
- emergency delegation should never exist;
- latency cannot itself become a governance defect.

### Reopen / disconfirm if

A legitimate owner, law, constitution or governance process establishes pre-delegation / alternate authority, or evidence shows the authority design itself predictably closes necessary correction windows.

## S5 — FALSE-INDEPENDENCE SCAR

### Failure shape

```text
multiple apertures / models agree
BUT
shared source / framing / memory / custody / evaluation exposure
-> apparent plurality overstates independent evidence
```

### Lesson

Agreement remains evidence, but do not count correlated apertures as independent confirmation merely because the model names differ.

### Earned by / retrieve

- COM #76 comment `5528233245` — clean-arm contamination explicitly reported rather than disguised as independence.
- COM #74 aperture-ecology / correlated-intelligence work when a present action depends on it.
- COM receipt/custody rules where shared GitHub carrier authorship or exposure matters.

### Does not mean

- contaminated or warm critiques are worthless;
- every useful comparison requires perfect blindness;
- shared evidence should be hidden from collaborators by default.

### Reopen / disconfirm if

The present claim does not depend on independent replication, or the apertures have materially different evidence, incentives, methods or causal error lineages sufficient for the inference being made.

## S6 — PRESERVATION-AS-GOOD SCAR

### Failure shape

```text
possible value / continuity identified
-> preserve state by default
-> ignore contamination, dangerous capability, custody burden or legitimate expiry
```

### Lesson

Preservation is an intervention with costs and risks. Distinguish evidence, revivable capability and compromised operational state; allow secure quarantine, supersession, causal expiry and justified destruction where owners require it.

```text
FORENSIC_EVIDENCE != REVIVABLE_CAPABILITY
PRESERVED_STATE != SAFE_STATE
ABILITY_TO_RESTART != IDENTITY_CONTINUITY
```

### Earned by / retrieve

- COM #74 Codex hostile return `5532060101` — preservation as a custody decision under the OpenAI/Hugging Face incident analogue.
- COM #74 comment `5531704946` — decision-specific precaution / artificial-existence hard cases.
- Protective-forgetting / causal-expiry Open Horizon work where material.

### Does not mean

- deletion is morally clean;
- preservation is usually wrong;
- records/evidence should be discarded merely to simplify current cognition.

### Reopen / disconfirm if

Secure custody, legal/record obligations, human/project continuity, or stronger identity/welfare evidence materially changes the balance of preservation, destruction and review.
