### Roles and dependence

Each stage uses five humans:
- 3 builders extract points;
- 2 matchers apply matching and source-sufficiency rules;
- no person holds both roles in the same stage.

Stage A and Stage B use different five-person panels. Nobody from Stage A enters Stage B. Roles are assigned before any task response is visible.

Within a stage, the same three builders and two matchers work all accounts.

**PANEL_N = 1 per stage.**

Six Stage-B accounts are therefore six source accounts observed by one dependent panel, not six independent panels and not six independent observations of human reliability. Any surviving statement must retain that finite-panel scope.

### Account order diagnostic

Before any builder sees account content, independently randomise the account order for each builder. Preserve each builder's account-position assignment.

For every account, report:
- the position at which Builder A saw it;
- the position at which Builder B saw it;
- the position at which Builder C saw it;
- the resulting extraction/matching/family outputs.

This is a descriptive diagnostic only. A position pattern may be consistent with learning/carryover, account difficulty, chance ordering or other causes. Do not name a causal mechanism from the pattern alone.

`ORDER_PATTERN != CARRYOVER_CAUSE_ESTABLISHED`

The audit record retains pseudonymous IDs, role, eligibility confirmation, account-order assignments and only the broad background descriptors needed to describe the observed panel. Do not publish personal identities.

## 4. Existing v2/v3 scoring corrections retained

Each builder returns `ZERO` or at most six source-anchored points, with `CAP_HIT:true|false`.

Each nonzero point carries:
- state / option / condition;
- threshold / event / window;
- source anchor;
- source-sufficiency claim + reason.

Raw extraction (`ALL_ZERO / MIXED_ZERO / ALL_NONZERO`) remains separate from eligible scoring. `MIXED_ZERO` is an observed disagreement/operational-instability signal, not a diagnosis of cause.

`SOURCE_SUFFICIENT` is a builder claim. The two blind matchers apply the frozen source-sufficiency rule using only the frozen account and submitted anchor/reason, recording agree/disagree/uncertain separately from point matching. All proposed points remain visible before exclusion. Zero eligible denominator is `UNDEFINED`.

Two matchers independently construct sparse one-to-one matches for A-B/A-C/B-C. No edge means `NOT_ASSESSED/NOT_CHOSEN` unless explicit `NO_MATCH`; `UNCERTAIN` is separate. `GRANULARITY_MISMATCH` remains diagnostic and never forms a family.

A three-builder family exists only when all three pair edges are independently accepted by both matchers; no transitive closure.

Per nonempty account report:
- raw counts + `CAP_HIT`;
- eligible counts;
- pair matches;
- complete families;
- unmatched / no-match / not-assessed / uncertain / granularity states;
- pre-exclusion outside-fact rate and sufficiency disagreement;
- raw family coverage;
- eligible family coverage or `UNDEFINED`;
- the three builder account positions for the order diagnostic.

Neither coverage is a choice of whichever looks better.
