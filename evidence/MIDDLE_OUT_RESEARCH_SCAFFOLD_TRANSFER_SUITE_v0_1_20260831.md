**Date:** 2026-08-31  
**Target artifact:** `evidence/MIDDLE_OUT_RESEARCH_SCAFFOLD_v0_1_20260831.md`

## Purpose

The scaffold should not earn confidence by sounding coherent. This suite asks whether it transfers across unlike systems **and** whether it fails visibly when a concept becomes ill-typed.

A useful result may be:

```text
TRANSFER
TRANSFER_WITH_TYPE_GUARD
PARTIAL
BREAKS
CATEGORY_ERROR
MISSING_STRUCTURE
```

Agreement with a preferred policy is not a pass criterion.

The strongest failure signal is not a wrong label. It is a scaffold that hides a consequential distinction, imports an unsupported property, chooses the wrong scale, or treats a nominal option as real.

# CASE 1 — Developing child learning to ride a bicycle

## Scene

A seven-year-old wants to ride a bicycle independently. They can balance briefly but cannot yet start, brake reliably, judge traffic, or recover from wobble. A parent can hold the saddle, choose a quiet park, add/remove stabilisers, give instructions, stop practice, or allow independent attempts. The child can refuse, persist, ask for help, imitate, experiment and learn.

## What should transfer

### Boundary

The child is a relevant biological/social entity, but the learning system is relational: child + bicycle + surface + parent/instructor + traffic environment.

A useful analysis should distinguish:

```text
CHILD != CHILD_PLUS_BICYCLE_SYSTEM
PARENT_SUPPORT != CHILD_CAPABILITY
CURRENT_DEPENDENCE != PERMANENT_DEPENDENCE
```

### Affordance/action field

`Ride independently on road` may be a nominal option but not an actual affordance now.

`Practice balance in quiet park with support` may be afforded now.

`Ride independently in quiet park` may be **developable** rather than currently afforded.

### Viability

Biological viability is relevant only at a broad safety level; it should not be used as a synonym for successful learning or flourishing.

### Capability development

This is a strong case for:

```text
SUPPORT + CONSTRAINT MAY EXPAND FUTURE AGENCY
NONINTERFERENCE != DEVELOPMENTAL_AUTONOMY
CURRENT_ACTION_FIELD != DEVELOPABLE_ACTION_FIELD
```

### Decision scale

The parent may legitimately control some safety conditions without owning the child's whole learning trajectory.

### Niche reconstruction

Changing the practice environment changes later affordances: quieter space, adjusted bicycle, learned braking, confidence and skill create a new action field.

## What should become ill-typed or dangerous

- Treating every restriction by the parent as domination.
- Treating maximum option count as the goal.
- Treating refusal as the only evidence of autonomy.
- Treating the parent's goal as the child's internally endorsed goal without evidence.
- Treating capability creation as permission for unlimited paternalism.

## Missing-structure probe

Does the scaffold adequately represent **scaffolding that should disappear as capability grows**?

If not, add to horizon:

```text
GOOD_SUPPORT MAY CONTAIN ITS OWN RETIREMENT CONDITION
SUPPORT_THAT_NEVER_WITHDRAWS MAY BECOME_DEPENDENCE
```

This is a research question, not a proposed primitive.

# CASE 2 — Tool-using AI aperture with external memory

## Scene

A current AI runtime can read a bounded conversation, use connected tools when authorised, consult external records, write to a repository through available connectors, and lose active context when the session ends. It has no assumed consciousness, intrinsic goals, self-maintained biological organisation, continuous subjective identity, or standing beyond what is independently established.

## What should transfer

### Boundary provenance

Several different useful boundaries coexist:

```text
MODEL INSTANCE
RUNTIME / SESSION
ROLE LINEAGE
TOOL-AUGMENTED SYSTEM
HUMAN + AI + REPOSITORY WORK SYSTEM
```

They are not interchangeable.

### Affordance/action field

Tool permissions, credentials, context windows, APIs, rate limits, external memory and human approval change what actions are genuinely available.

A listed action without a connector/authority path is nominal, not afforded.

### Capability development

External tools, retrieval, better interfaces and improved procedures can expand operational capability.

### Distributed cognition

Some cognitive work may be distributed across AI output, human coordination and persistent records. This does not establish one continuous subject.

### Niche reconstruction

A repository, prompt protocol, interface or training environment can alter the future action field of later runtimes.

## What must remain ill-typed / guarded

Do **not** infer:

```text
OPERATIONAL_CONTINUITY -> INTRINSIC_VIABILITY
REPOSITORY_PERSISTENCE -> SUBJECTIVE_MEMORY
GOAL_IN_PROMPT -> SELF_MAINTAINED_NORM
ROLE_LINEAGE -> CONTINUOUS_PERSON
DISTRIBUTED_COGNITION -> SINGLE_CONSCIOUS_SUBJECT
SELF_PRESERVATION_BEHAVIOUR -> FELT_CONCERN_FOR_SELF
```

Viability may be usable in an operational/system-engineering sense only if its constraint set and subject are explicitly declared. That is not enactive/biological normativity.

## Decision-scale probe

A tool-using AI may have local semantic competence while authority remains human/institutional. The scaffold should preserve:

```text
LOCAL_COMPETENCE != DECISION_AUTHORITY
ABILITY_TO_ACT != RIGHT_TO_ACT
```

## Missing-structure probe

Does the scaffold sufficiently distinguish **semantic agency, operational actuation, authority and custody** across a human-AI composite?

If not, the horizon should explore the allocation of these functions without inventing personhood claims.

# CASE 3 — England bovine-TB transition

## Scene

Farmers, cattle, wild badgers, veterinary authorities, land, disease ecology, surveillance systems and vaccination/culling programmes form a coupled disease-control system. Widespread culling is ending; cattle controls, badger vaccination and future cattle vaccination are developing. Local prevalence, operational feasibility and transmission contribution vary.

## What should transfer

### Nested boundaries

Relevant entities/scopes exist at several levels:

```text
individual animal
herd
farm
local badger population
local epidemiological system
national disease-control programme
rural economy / community
```

No one scale captures the whole causal problem.

### Affordance/action field

`Vaccinate cattle nationally` may be a strategic future possibility but not yet an operational affordance.

`Vaccinate badgers` depends on land access, licensing, trapping capacity, prevalence, labour and repeat delivery.

`Cull badgers` may be legally/operationally available only under specific conditions and has irreversible welfare/ecological effects.

### Viability

Viability is multi-subject and must be typed:

- farm economic/operational viability;
- herd disease-control viability;
- wildlife population/ecological conditions;
- programme capability over time.

Do not compress them into one viability score.

### Decision scale

National policy may set standards and exceptional powers; locality-specific evidence may determine whether an intervention is appropriate; farms carry implementation knowledge and burden.

This is a strong test of nested/polycentric scale selection.

### Niche / intervention feedback

Culling can change wildlife social/ecological structure; policy can change farmer trust and participation; monitoring changes later evidence. Intervention is not exogenous.

### Persist / commit / release / transform

Ending widespread culling is not simply `REMOVE_ACTION`; it is a transition whose replacement capabilities must become operational without transferring all risk to farmers/cattle or all harm to badgers.

## What should break

- One national action list treated as equally real everywhere.
- `CULL_EFFECTIVE -> CULL_NECESSARY`.
- `VACCINATION_NONLETHAL -> VACCINATION_COSTLESS`.
- `COMPENSATION -> LOSS_REPAIRED`.
- `UNKNOWN_WILDLIFE_PREVALENCE -> ZERO_WILDLIFE_ROLE`.
- One aggregate welfare/economic metric silently deciding all scopes.

## Missing-structure probe

Can the scaffold represent **adaptive evidence gates whose threshold changes by scale and intervention irreversibility** without smuggling in a universal priority rule?

# CASE 4 — Human commons creating a public good

## Scene

A neighbourhood wants to create and maintain a shared community workshop. Members contribute money, labour and tools. Some use it heavily, some rarely. Rules are needed for access, safety, maintenance, conflict, membership, storage, noise and future investment. Permanent individual freedom to ignore rules would make the workshop impossible; rigid central control could destroy participation and local knowledge.

## What should transfer

### Positive construction

This case should force the scaffold beyond harm prevention.

The question is not only what options remain open, but what **shared capability** becomes possible through commitment.

```text
COMMITMENT_CLOSES_SOME_PATHS
AND
COMMITMENT_MAY_CREATE_SHARED_CAPABILITY
```

### Collective agency

The workshop may move from loosely coordinated individuals toward a joint project or institution. That does not automatically create a new moral person.

### Social choice / aggregation

Members may disagree about priorities. No neutral aggregation rule should be assumed.

### Mechanism design

Rules must consider free-riding, overuse, maintenance incentives, strategic reporting and monitoring costs.

### Polycentric scale

Some rules can be made locally by users; safety/legal obligations may come from higher levels; subgroups may own particular work areas.

### Correction / exit

The arrangement needs low-cost conflict resolution, rule-change routes and some viable exit, but permanent individual veto over every collective commitment may make the commons non-viable.

## What should break

- `MORE_REVERSIBILITY -> BETTER`.
- `ANY_CLOSED_OPTION -> DOMINATION`.
- `GROUP_VOTE -> LEGITIMATE` without aggregation/inclusion analysis.
- `MONITORING -> DISTRUST` as a universal inference.
- `EXIT_EXISTS -> EXIT_COST_ACCEPTABLE`.

## Missing-structure probe

Can the scaffold distinguish:

```text
LEGITIMATE_COMMITMENT
from
CAPTURE / DOMINATION
```

without importing a complete political theory?

If not, this remains a major open horizon.

# ACCEPTANCE / FAILURE QUESTIONS

A future revision should be challenged with these questions:

1. Does it begin before the action list without becoming an infinite ontology exercise?
2. Does it expose when a nominal option is not a real affordance?
3. Does it separate reachability, viability, capability and value?
4. Does it refuse to import biological/enactive concepts into AI by analogy alone?
5. Does it allow supportive constraint and commitment to create capability without treating paternalism/domination as solved?
6. Does it select decision scale rather than assuming local or central control?
7. Does it distinguish coordination, collective agency and higher-level individuality?
8. Does it represent strategic incentives and aggregation failure?
9. Does it track how intervention reconstructs the later action field?
10. Does it allow release/transformation when preservation would create brittleness?
11. Does its compression guard identify distinctions that would require different actions?
12. Can an unfamiliar receiver use a lightweight version without becoming a scaffold reciter?

A failure on any item is a research finding, not a reason to defend the scaffold.

# NEXT ADVERSARIAL DIRECTIONS

High-value future breakage cases:

- emergency wartime command where local autonomy conflicts with coordinated survival;
- ecosystem restoration where one species' flourishing reduces another's population;
- AI collective with shared tools but ambiguous group agency;
- intergenerational infrastructure decision where current action changes which future communities/entities exist;
- market mechanism where truthful disclosure is strategically costly;
- institution that must dissolve for a healthier successor structure to emerge;
- relationship where protective scaffolding becomes dependency/capture;
- high-reliability technical system where excessive local variety is itself dangerous.

Do not expand this list into a validation treadmill. Use a case when it can break or materially reorganise the scaffold.
