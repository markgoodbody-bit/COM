### Roles

Each stage uses five humans:
- **3 builders** extract points;
- **2 matchers** match builder point sets and perform the frozen source-sufficiency review role;
- no person may hold both roles in the same stage.

Stage A and Stage B use **different five-person panels**. Nobody from Stage A may enter Stage B.

Within a stage, the same three builders and same two matchers work all accounts in that stage. This deliberately controls person-to-person variance while testing instruction/account stability. It also limits the claim: Phase 0 does not establish general-population reliability.

Builder/matcher identities are not published as personal data; the audit record retains pseudonymous IDs, role, eligibility confirmation and the broad background descriptors needed to state the population honestly.

## 4. Existing v2 + accepted freeze deltas retained

### Builder returns

Each builder may return `ZERO` or at most six source-anchored points. Every return records `CAP_HIT: true|false`.

Each nonzero point retains:
1. state/option/condition;
2. threshold/event/window;
3. source anchor;
4. source-sufficiency claim + reason.

Raw extraction state (`ALL_ZERO / MIXED_ZERO / ALL_NONZERO`) remains separate from eligible scoring state. `MIXED_ZERO` is an observed extraction disagreement/operational-instability signal, not a diagnosis of cause.

### Source sufficiency

`SOURCE_SUFFICIENT` is a builder claim, not reviewed fact. The two blind matchers apply the frozen source-sufficiency rule using only the frozen account and submitted anchor/reason. They record agree/disagree/uncertain separately from point matching.

All proposed points remain visible before any source-sufficiency exclusion. Zero eligible denominator is `UNDEFINED`, never zero and never silently dropped.

### Matching

Two matchers independently construct sparse one-to-one matches for A-B, A-C and B-C. Absence of an edge is `NOT_ASSESSED/NOT_CHOSEN` unless the matcher explicitly records `NO_MATCH`; `UNCERTAIN` is separate.

`GRANULARITY_MISMATCH(Ai,{Bj,Bk})` (or symmetric equivalent) is a diagnostic state for broad/split relationships that one-to-one matching cannot accept. It never forms a family and cannot repair Stage-B consensus after the outcome is visible.

A three-builder family exists only when all three pair edges are independently accepted by both matchers; no transitive closure.

### Descriptive outputs

For each nonempty account report at minimum:
- raw builder counts and `CAP_HIT` status;
- eligible source-supported counts;
- accepted pair matches and complete three-builder families;
- unmatched points, explicit no-match, not-assessed, uncertain and granularity-mismatch states;
- pre-exclusion outside-fact/source-insufficiency rate and matcher sufficiency disagreement;
- **raw family coverage** = family-participating submitted points / all submitted points;
- **eligible family coverage** = family-participating eligible points / eligible points, or `UNDEFINED` if denominator is zero.

Neither coverage is a second chance to choose whichever looks better.
