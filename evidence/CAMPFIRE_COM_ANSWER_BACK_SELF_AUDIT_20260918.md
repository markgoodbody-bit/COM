## What Campfire Relay actually claims

The README describes a local-first multi-model research relay whose central responsibilities include:
- freezing prompt/context/sources/controls;
- dispatching differentiated model apertures;
- preserving each return independently;
- preserving silence, failure, truncation and wrong-input states;
- comparing divergence;
- maintaining append-only evidence / hashes / receipts / closure checkpoints;
- keeping spending authority and runtime activation bounded.

That is primarily a **transport / evidence / research-control** contract.

It is not documented as:
- a whistleblower channel;
- continuous public-thread monitoring;
- a general incident-response system;
- an enforcement authority;
- an institutional grievance mechanism.

Therefore:

```text
CAMPFIRE_RELAY != ANSWERABILITY_SYSTEM_BY_DEFINITION
RESEARCH_RETURN_PRESERVED != EXTERNAL_REPORT_MONITORED
DEBATE_CLOSED != WORLD_CORRECTED
```

## Does this earn a build?

Not yet.

The answer-back field cases show that monitoring/timeliness can matter, but this self-audit has not reproduced a missed consequential project reply caused by absent monitoring in the current setup.

Current operating discipline already reduces the risk through explicit COMSYNC and source re-read.

A watcher/notification mechanism would be justified only by a concrete need such as:
- a consequential external critique repeatedly remaining unseen long enough to distort active work;
- a real resource/opportunity deadline depending on a reply;
- a public safety/correction route whose promised responsiveness exceeds manual COMSYNC practice.
