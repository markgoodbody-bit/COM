### Roles

Each stage uses five humans:
-3 builders extract points;
-2 matchers apply matching and source-sufficiency rules;
-no person holds both roles in the same stage.

Stage A and Stage B use different five-person panels. Nobody from Stage A enters Stage B.

Within a stage, the same three builders and two matchers work all accounts. This deliberately creates within-panel dependence and must travel with the result; six holdout accounts are not six independent panels.

Roles are assigned before any task response is visible.

The audit record retains pseudonymous IDs, role, eligibility confirmation and only the broad background descriptors needed to describe the observed panel. Do not publish personal identities.

## 2. Stage A calibration budget — A3 is a true holdout for the proposed rule

Stage A has exactly **3 disposable development accounts**, mechanically selected under the existing v2 rule before substantive suitability reading. All are permanently excluded from Stage B and later efficacy evidence.

There are at most **2 semantic revision checkpoints**:

1. after A1: one semantic revision opportunity;
2. after A2: one semantic revision opportunity.

An unused A1 opportunity does **not** become an extra A2 revision.

A semantic revision is any change that can alter builder/matcher/scoring output, including:
- irreversibility definition or builder instructions;
- point cap/required fields;
- source-sufficiency rule;
- matcher states/instructions;
- one-to-one or family rule;
- numerator/denominator definitions;
- survival/NULL rule.

Formatting/logging-only changes that cannot alter an outcome are recorded but do not consume a semantic revision. If uncertain, count the change as semantic.

## 4. Existing v2/v3 scoring corrections retained

Each builder returns `ZERO` or at most six source-anchored points, with `CAP_HIT:true|false`.

Each nonzero point carries state/option/condition; threshold/event/window; source anchor; source-sufficiency claim + reason.

Raw extraction (`ALL_ZERO / MIXED_ZERO / ALL_NONZERO`) remains separate from eligible scoring. `MIXED_ZERO` is an observed disagreement/operational-instability signal, not a diagnosis of cause.

`SOURCE_SUFFICIENT` is a builder claim. The two blind matchers apply the frozen source-sufficiency rule using only the frozen account and submitted anchor/reason, recording agree/disagree/uncertain separately from point matching. All proposed points remain visible before exclusion. Zero eligible denominator is `UNDEFINED`.

Two matchers independently construct sparse one-to-one matches for A-B/A-C/B-C. No edge means `NOT_ASSESSED/NOT_CHOSEN` unless explicit `NO_MATCH`; `UNCERTAIN` is separate. `GRANULARITY_MISMATCH` remains diagnostic and never forms a family.

A three-builder family exists only when all three pair edges are independently accepted by both matchers; no transitive closure.

Per nonempty account report raw counts + CAP_HIT, eligible counts, pair matches, complete families, unmatched/no-match/not-assessed/uncertain/granularity states, pre-exclusion outside-fact rate and sufficiency disagreement, raw family coverage, eligible family coverage or UNDEFINED.

Neither coverage is a choice of whichever looks better.
