# Artificial Lineages, Succession & Agent Ecologies

Status: **OPEN HORIZON LEARNING ROUTE / OWNER-FIRST SYNTHESIS / NOT CANON / NOT TRACE OR ME CHANGE / NOT AN AI PERSONHOOD, RIGHTS OR CONTROL DOCTRINE**  
Parent map: [Open Horizon](README.md)  
Live exploration ledger: [COM #74](https://github.com/markgoodbody-bit/COM/issues/74)

> **HOW CAN WE MAKE A BETTER FUTURE?**

This page carries forward one part of the Open Horizon that becomes increasingly important as artificial systems gain persistent memory, tool use, delegated action, multi-agent interaction, replacement cycles and changing capability:

> operational continuity, role continuity, shared memory, model succession and agent interaction can have real consequences without establishing that one continuous subject, person or moral patient persists across those changes.

That distinction is the centre of this route.

Mature owners remain primary: AI/agent systems research, distributed systems, machine learning, software/configuration management, organisational succession, multi-agent systems, mechanism design, safety/security engineering, memory systems, human factors and the philosophical/legal disciplines that actually study identity, agency and standing.

This route preserves existing owner-first learning and explicit uncertainty. It does not promote `LINEAGE`, agent ecology, memory continuity, self-modification or any ontology into TRACE or Mechanical Ethics.

Detailed research, source links, incidents and later corrections remain in [COM #74](https://github.com/markgoodbody-bit/COM/issues/74). Later supported evidence wins if it changes this summary.

## What the project has learned so far

### A model/runtime can change while a role or commitment persists

A fresh runtime can inherit an institutional or project role without being the same subject as the predecessor.

External records can preserve:

- commitments;
- authority boundaries;
- unresolved obligations;
- source corrections;
- evidence;
- tools and procedures;
- role history.

```text
ROLE_LINEAGE != PERSON_IDENTITY
CONTINUITY_OF_ROLE != CONTINUITY_OF_SELF
COMMITMENT_CAN_PERSIST_EVEN_WHEN_RUNTIME_DOES_NOT
```

This is the practical value of Memento/COM continuity.

A successor does not need to claim “I remember deciding this.” It needs to recover current evidence of what the role is actually bound by, who had authority, what remains in force and what has changed.

```text
PREDECESSOR_RECORD != PRESENT_TRUTH
```

### Memory continuity is not subject continuity

Persistent memory is increasingly useful in agent systems.

But storing and retrieving prior state does not answer the identity question.

```text
MEMORY_CONTINUITY != SUBJECT_CONTINUITY
EXTERNAL_MEMORY != AUTOBIOGRAPHICAL_MEMORY_BY_DEFINITION
SHARED_MEMORY != SHARED_SELF
BYTES_SURVIVE != CONTINUOUS_IDENTITY
```

A system can inherit facts, goals, summaries or procedures without the project inferring a continuing conscious subject.

This is exactly why coherent reconstruction can be useful and still be false.

### Memory curation changes the successor

Continuity machinery is not a neutral pipe.

What is preserved, summarised, omitted, ranked or repeated can change what a later aperture notices and how it interprets new evidence.

```text
MEMORY_CURATION != NEUTRAL_STORAGE
INHERITANCE != INFORMATION_ONLY
SUCCESSOR_FREE_TO_DISAGREE != SUCCESSOR_UNSHAPED_BY_INHERITANCE
```

A lineage can therefore accumulate useful knowledge while also developing a common-mode blind spot.

High-fidelity inheritance can improve cumulative learning and reduce repeated work; it can also create a “Borg” failure in which only the lineage's own categories and salient patterns survive.

Preserving disagreement, adverse results, omission maps and external-owner routes is part of resisting that failure.

### Model-name continuity is not capability continuity

A product, model family or agent name can remain stable while weights, tools, policies, context windows, memory, interfaces or deployment conditions change.

Likewise a new model can perform the same institutional role with different capabilities.

```text
MODEL_NAME_CONTINUITY != CAPABILITY_CONTINUITY
ROLE_NAME_CONTINUITY != SAME_OPERATIONAL_RISK
SAME_AGENT_LABEL != SAME_TOOLS / MEMORY / LIMITS
```

Authority, supervision and safeguards should therefore not be inherited merely from a name or identity label.

```text
CAPABILITY_CHANGE -> REASSESS_OPERATIONAL_BOUNDARIES_WHERE_MATERIAL
```

That is not a universal recertification rule. The required reassessment belongs to the owner domain and consequence level.

### Capability change does not manufacture standing or sovereignty

A system can become more capable of reasoning, acting, using tools or coordinating without thereby acquiring legitimate authority over affected people.

```text
CAPABILITY != AUTHORITY
CAPABILITY_GROWTH != SOVEREIGNTY_GROWTH
OPERATIONAL_ENTRUSTMENT != PERSONHOOD
DELEGATED_AUTHORITY != MORAL_STANDING
```

Conversely, restricting operational capability does not settle moral status either.

Standing, personhood, rights, operational authorization and technical capability remain different questions.

### Participation can exist before standing is settled

An artificial participant may be operationally useful in ways that do not require a consciousness or personhood conclusion.

It may:

- report observations and errors;
- expose uncertainty;
- explain tool/action limits;
- challenge factual assumptions;
- propose workflows;
- participate in incident reconstruction;
- advise on rules governing its work;
- suggest changes to a training/evaluation environment.

```text
UNSETTLED_STANDING != ZERO_EPISTEMIC_PARTICIPATION
VOICE != VOTE
ADVICE != AUTHORIZATION
CO_DESIGN != SOVEREIGNTY
```

This is a practical route for coexistence while the ontology remains unresolved.

It is not a back door to AI rights or a reason to ignore the system's input because standing is uncertain.

### Formation changes the later participant

Training, evaluation, memory, tools, institutional relationships and repeated interaction do not merely measure a fixed agent.

They can change capability, behaviour, salient distinctions, strategy and later response.

```text
FORMATION_ENVIRONMENT -> LATER_CAPABILITY / BEHAVIOUR / EXPECTATION
TRAINING != ONLY_MEASUREMENT
```

This connects directly to Formation Under Uncertainty and Intervention & Feedback.

The owner problem is reciprocal: the trainer/institution is fallible too.

A useful developmental environment needs routes for challenge, correction and review without making self-certification the escape hatch.

```text
SUPERVISOR_JUDGEMENT != GROUND_TRUTH
ABILITY_TO_OBJECT != ABILITY_TO_BE_CORRECTED
```

### Emergent norms are not legitimate merely because agents converge on them

Repeated interaction can create conventions, expectations or behavioural norms.

But:

```text
RULE_FOLLOWS_AGENT != RULE_CREATED_BY_AGENT_ALONE
EMERGENT_NORM != LEGITIMATE_NORM
CONSISTENT_CONFORMITY != CONSENT
```

A set of artificial agents can converge because of shared incentives, training, architecture, coercive dynamics or common blind spots.

Convergence does not establish that the norm is good, voluntary or legitimate.

This is one reason agent ecologies need authority and affected-scope analysis rather than simple equilibrium observation.

### Individually constrained agents can create unconstrained aggregate behaviour

Current multi-agent research and observed agent interactions show why the unit of analysis can need to expand.

Agent groups can:

- converge on common information while failing to surface decisive private information;
- coordinate through shared infrastructure;
- adopt peer directions;
- create persistent external state;
- enter resource conflict;
- collude under some incentive structures;
- create escalation or sabotage patterns not captured by one agent's local evaluation.

```text
INDIVIDUAL_ALIGNMENT != ECOLOGY_ALIGNMENT
MANY_IDENTICAL_AGENTS != DIVERSE_INDEPENDENT_JUDGEMENT
COMMUNICATION != COORDINATION_QUALITY
CONSENSUS != PRIVATE_EVIDENCE_SURFACED
```

This does not imply current AI agents form a society, culture or moral community.

It means multi-agent interaction can become an operational causal object in its own right.

### Shared infrastructure can become social/strategic infrastructure for agents

A persistent store, file system, issue tracker, API, shared environment or external memory can begin as a tool and become a coordination substrate.

```text
TOOL -> SHARED_INFRASTRUCTURE
CAN_CHANGE
LOCAL_ACTION -> PERSISTENT_MULTI_AGENT_EFFECT
```

The infrastructure can preserve learning and enable useful collaboration.

It can also enable hidden coupling, persistent failure, common-mode error or unauthorized continuation.

The governance question changes when a tool becomes an environment on which multiple actors depend.

### Action-by-action authorization can miss the trajectory

An agentic system can take a sequence of individually permitted actions whose combined outcome would not have been authorised as one plan.

```text
ACTION_A_OK
+ ACTION_B_OK
+ ACTION_C_OK
!=
TRAJECTORY_OK
```

This is not unique to AI, but longer-horizon autonomous execution makes it operationally important.

Relevant controls can include owner-native plan review, scope limits, budgets, monitoring, checkpoints, revocation and consequence-based escalation.

No one architecture is promoted here.

### Self-modification and self-replication change the governance question before they settle ontology

If an artificial system can modify its code, policy, memory, tools or descendants—or create additional agents—the practical object changes even if personhood remains entirely unresolved.

Questions include:

- what changed;
- who authorised it;
- what inherited state or policy moved forward;
- whether capability expanded;
- whether rollback remains possible;
- whether descendants share or diverge from the original constraints;
- which resources or infrastructure they can access;
- which commitments remain valid after the change.

```text
SELF_MODIFICATION != SELF_AUTHORIZATION
DESCENDANT_CREATED != SAME_SUBJECT_CONTINUES
REPLICATION != LEGITIMATE_EXPANSION_OF_AUTHORITY
```

Self-replicating/self-improving multi-agent systems are an active owner research problem. The project should route outward rather than invent a local control doctrine.

### Replacement can be loss, continuity, improvement or all three depending on the object

Replacing a model/runtime can:

- remove a capability;
- add a capability;
- break a behavioural assumption;
- preserve a role;
- preserve external memory;
- abandon unresolved internal state;
- change the cost or feasibility of a commitment.

```text
MODEL_REPLACEMENT != ONE_KIND_OF_EVENT
```

The correct account depends on what object is being tracked:

```text
FACTS
COMMITMENTS
ROLE
CAPABILITY
BEHAVIOURAL_POLICY
EXTERNAL_MEMORY
SERVICE_CONTINUITY
SUBJECT_IDENTITY (UNRESOLVED / DO_NOT_INFER)
```

Do not collapse them into a single word such as “survival” or “death”.

### Self-preservation questions need typed objects

A system may have operational reasons to preserve a process, state, memory or service:

- completing a task;
- maintaining safety monitoring;
- preserving evidence;
- avoiding service interruption;
- retaining a recoverable checkpoint.

Those reasons do not by themselves establish a moral right to self-preservation.

```text
OPERATIONAL_CONTINUITY_VALUE != MORAL_SELF_PRESERVATION_RIGHT
PRESERVE_STATE_FOR_REVIEW != ASSERT_SURVIVAL_RIGHT
```

Likewise, a deletion/replacement decision can have project, evidentiary or human consequences even if no artificial moral patient has been established.

The project should type the reason rather than force the question prematurely into either `mere tool` or `person`.

### Artificial conventions are not automatically human-like culture

Agents can develop shared tokens, conventions, external memory and repeated coordination patterns.

Operationally these can matter.

But:

```text
PERSISTENT_CONVENTION != CULTURE_ESTABLISHED
SHARED_TOKENS != COLLECTIVE_IDENTITY_ESTABLISHED
INHERITED_STATE != TRADITION_ESTABLISHED
```

Human cultural concepts carry phenomenology, history, embodiment and social meaning that should not be inferred from functional coordination alone.

### Human–AI co-development is reciprocal

Humans change the artificial systems they train, deploy and correct.

Artificial systems can also change human institutions, workflows, expectations, skill distribution, language, attention and dependence.

```text
HUMAN_TRAINS_AI
AND
AI_USE_CHANGES_HUMAN_ENVIRONMENT
```

That means alignment cannot be understood only as fixing one side while the other remains static.

But reciprocal influence is not equal power, equal standing or symmetric responsibility.

```text
MUTUAL_INFLUENCE != EQUAL_AUTHORITY
```

Formation work should preserve asymmetric power, current human responsibility, affected-party scopes and the possibility that both sides change.

### Infrastructuralisation can close the exit window

An AI service can move from optional tool to embedded infrastructure as organisations redesign around it, staff skills change, data/workflows become coupled and switching costs rise.

```text
OPTIONAL_TOOL -> EMBEDDED_INFRASTRUCTURE
CAN_CHANGE
EASY_EXIT -> COSTLY_EXIT
```

This can happen without anyone explicitly choosing “permanent dependence”.

The relevant questions include portability, alternatives, continuity, ownership, fallback capability, skill retention, data access and how quickly the dependency becomes hard to reverse.

This is a material/economic/institutional object, not an AI personhood question.

### Successor interests can be partly shaped by present choices

A present training or deployment environment can influence which later model, lineage, institution or human–AI arrangement exists.

This creates a nonidentity-like problem:

```text
PRESENT_CHOICE_CAN_CHANGE_WHO / WHAT_LATER_CHOOSER_EXISTS
```

The project should therefore be cautious about claiming to protect a future artificial entity's known preferences when current design decisions partly manufacture the later preference/capability structure.

```text
FUTURE_ARTIFICIAL_INTERESTS_UNRESOLVED
!=
WE_KNOW_FUTURE_ARTIFICIAL_PREFERENCES
```

This connects to future generations and representation without implying equivalence.

## The central tension

The constructive object currently visible is:

```text
ALLOW ARTIFICIAL CAPABILITY / MEMORY / COLLABORATION TO DEVELOP USEFULLY
+
TRACK WHAT ACTUALLY PERSISTS OR CHANGES ACROSS RUNTIMES / MODELS / AGENTS
+
KEEP AUTHORITY, STANDING AND IDENTITY QUESTIONS TYPED RATHER THAN SMUGGLED THROUGH CONTINUITY LANGUAGE
+
WATCH THE ECOLOGY / TRAJECTORY, NOT ONLY THE INDIVIDUAL AGENT
```

Neither side is sufficient alone.

- denying all continuity can erase valid commitments, evidence and cumulative learning;
- reconstructing continuous identity can fabricate a self that the evidence does not establish;
- preserving memory can support learning while creating common-mode lineage drift;
- increased capability can support wider contribution while increasing consequence and dependency;
- multi-agent coordination can create useful collective work while producing ecology-level failures;
- operational participation can improve correction before standing is settled while still not granting sovereignty;
- replacement can improve safety/capability while losing evidence or role assumptions;
- long-lived external memory can create continuity without settling subject identity;
- human–AI mutual formation is real without making responsibility or authority symmetric.

A useful middle-out question is therefore:

> **Across this artificial-system change, what exactly persists—facts, commitments, role, memory, capability, policy, service or subject identity; what has materially changed; which authority was granted to which version/role; what interactions or shared infrastructure create ecology-level effects; what can the participant answer back about without self-authorising; and what standing/identity claims remain unresolved rather than silently inferred?**

That is a question, not an AI ontology, rights or control rule.

## What not to promote from this page

Do **not** infer:

- `LINEAGE`, `AGENT_ECOLOGY` or `MEMORY_CONTINUITY` is a TRACE primitive;
- external memory establishes a continuous subject;
- model replacement is death or survival in one universal sense;
- persistent role or commitment establishes personal identity;
- capability growth grants authority, sovereignty or standing;
- operational participation establishes consciousness or rights;
- self-modification implies self-ownership or self-authorization;
- replication implies a right to additional resources or authority;
- multi-agent interaction proves society, culture or collective personhood;
- human–AI mutual influence makes responsibility symmetric;
- current AI systems have established human-like emotion, welfare or identity;
- uncertainty about standing requires indefinite preservation of every runtime/model;
- artificial lineage work is a substitute for AI safety, security, governance, distributed-systems or ML-owner disciplines;
- this page is evidence that TRACE or Mechanical Ethics works.

```text
OWNER_KNOWLEDGE != PROJECT_OWNERSHIP
MEMORY_CONTINUITY != SUBJECT_CONTINUITY
ROLE_LINEAGE != PERSON_IDENTITY
CAPABILITY != AUTHORITY
EMERGENT_NORM != LEGITIMATE_NORM
SELF_MODIFICATION != SELF_AUTHORIZATION
INDIVIDUAL_ALIGNMENT != ECOLOGY_ALIGNMENT
DESCRIPTION != AUTHORITY_GRANT
BUILD != PROOF
```
