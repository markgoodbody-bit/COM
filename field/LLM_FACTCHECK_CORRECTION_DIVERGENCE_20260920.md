> HOW CAN WE MAKE A BETTER FUTURE?

## Real pressure

Full Fact reports a five-month trial in which leading LLM/chatbot systems were asked about false claims circulating online.

Published 28 August 2026 and updated 2 September, the analysis reports:
- 39 major errors;
- 67 mistaken responses across the different models;
- some systems later corrected themselves, often citing Full Fact's published fact checks;
- other systems continued to return incorrect answers after the fact check had been published.

A non-political example in the report is an AI-generated Ryanair cabin-window image that several models initially described as real.

Owner sources:
https://fullfact.org/technology/full-fact-analysis--ai-chatbots-misinformation/

## Thin relation

```text
FALSE / MISLEADING CLAIM
-> MODEL RESPONSE AT T0
-> PUBLIC FACT CHECK / CORRECTION
-> MODEL RESPONSE AT T1

T1 MAY:
-> CORRECT
-> PERSIST
-> CHANGE PARTLY
-> CITE THE FACT CHECK
-> USE A DIFFERENT SOURCE
```

Therefore:

```text
FACT CHECK PUBLISHED != MODEL CORRECTED
ONE CARRIER CORRECTED != ALL CARRIERS CORRECTED
SAME QUESTION != SAME ANSWER OVER TIME
MODEL LABEL != PERSISTENT RESPONSE OBJECT
PUBLIC CORRECTION != OBSERVED INGESTION / PROPAGATION
```

This is a real correction-propagation and currentness problem.

## Strongest owner

Full Fact is already building a continuous public-interest LLM benchmark.

Its current owner description says it:
- asks leading models the same questions every day;
- stores the responses;
- has collected more than 11,000 responses so far;
- evaluates factuality, transparency, timeliness, consistency and civic responsibility;
- is intended to be publicly available and auditable;
- explicitly aims to detect drift, regression and inconsistency over time.

This is substantially stronger ownership of **LLM output monitoring and benchmark evaluation** than THR should attempt to reproduce.

The first benchmark report is stated by Full Fact to be due in mid-October 2026.

## Pressure on THR / RFC #52

This case is relevant to the held THR fractal RFC because it supplies genuine:
- repeated observation over time;
- multiple carriers/models;
- correction divergence;
- source/currentness change;
- a need to distinguish correction publication from downstream correction.

But it does **not** supply the RFC's missing multi-record THR fan-out case.

```text
MULTIPLE MODEL RESPONSES != MULTIPLE THR RECORD DEPENDENCIES

EXTERNAL CORRECTION DIVERGENCE != THR NEEDS A CORRECTION-PROPAGATION TYPE
```

The current narrowed RFC already says:
- generic correction propagation is not THR-owned;
- upstream correction does not auto-correct downstream objects;
- changed load-bearing evidence routes dependents to review;
- review required != invalid.

The Full Fact owner evidence strengthens that subtraction.

## Surviving THR-shaped residue

Potential THR value remains narrower:
- preserve which exact external response/version was actually observed when a THR record relies on it;
- preserve the evidence ceiling at that observation time;
- preserve whether a later correction was actually re-observed;
- avoid counting multiple model outputs as independent evidence merely because they are different endpoints.

That is already expressible with current source / observation / assertion / record-local machinery.
