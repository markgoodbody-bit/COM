# Great Britain data-centre grid connections — material reachability field case — 18 September 2026

Status: **REAL PUBLIC INFRASTRUCTURE FIELD CASE / ELECTRICITY-CONNECTION REFORM / OWNER-RICH / NOT ENERGY POLICY ADVICE / NOT AI-LOAD JUDGMENT / NOT TRACE-ME CANON**

Primary current owners:
- Ofgem, Proposed data centre connection reforms, 29 July 2026, consultation now closed;
- National Energy System Operator (NESO), connections reform/current pipeline materials;
- UK Government / Ofgem / NESO demand-connections reform.

Purpose: preserve a current case where nominally financeable/planned digital capacity is constrained by slower physical infrastructure, long-lead equipment and shared-system reliability.

## Current public pressure

Ofgem reports demand-connection applications rising from 41GW to 125GW in under a year, driven largely by data-centre projects, with around 73-80GW of data-centre demand referenced in current reform material.

Ofgem/NESO say the demand queue contains a material volume of non-viable/speculative projects that can impede planning and delay viable projects.

Current reform proposals include:
- a data-centre commitment fee;
- queue-management milestones;
- evidence of a credible end user;
- evidence of long-lead electrical equipment procurement, for example switchgear;
- evidence of financial and technical capability;
- stronger curation/planning/connection rules.

NESO says the old queue reached roughly four times what Britain needed for 2030 energy needs and that access to the national electricity network can determine whether industrial/data-centre investment proceeds or is delayed.

## Material conversion path

The case makes a physical capability chain visible:

```text
DATA-CENTRE / COMPUTE PROJECT DESCRIBED
-> CREDIBLE END USER / FINANCE
-> SITE / PLANNING / CONNECTION APPLICATION
-> LONG-LEAD ELECTRICAL EQUIPMENT
-> NETWORK / GENERATION CAPACITY
-> CONNECTION OFFER / BUILD
-> PHYSICAL ENERGISATION
-> OPERATION UNDER SYSTEM-STRESS RULES
```

Failure at any link can make the compute project practically unreachable even if software, capital or market demand exist.

```text
SOFTWARE PLAN EXISTS != POWER CONNECTION REACHABLE
CAPITAL AVAILABLE != GRID CAPACITY AVAILABLE
QUEUE POSITION != REALISTIC CONNECTION PATH
CONNECTION OFFER != PHYSICALLY ENERGISED CAPABILITY
```

## Clock mismatch

The digital/financial planning cycle can move much faster than transmission, generation and equipment build.

Ofgem explicitly refers to long-lead equipment. Current reform material also says well-progressed projects can be unable to connect quickly because network/generation build takes time.

```text
COMPUTE DEMAND CLOCK
!=
GRID / TRANSFORMER / SWITCHGEAR / GENERATION BUILD CLOCK
```

This is a real current example of:

```text
DECISION_SPEED != PHYSICAL_PROCESS_SPEED
SYSTEM_DEADLINE != MATERIAL_WORLD_CAN_ACCELERATE_TO MATCH
```

## Shared-system consequence

Connection capacity is not a purely private property of one project.

Speculative/non-viable projects can occupy planning/queue attention and distort future network planning. Very large data-centre loads also create system-stress questions.

Ofgem's June reform update discusses voluntary flexibility/alternative connection agreements and possible backstop operational-control measures such as curtailment under stress, while acknowledging that different data-centre business models have different tolerance for interruption.

Thus:

```text
PRIVATE PROJECT DEMAND != ONLY PRIVATE CONSEQUENCE
AI / DATA-CENTRE LOAD != ONE INFLEXIBLE LOAD
FLEXIBILITY != UNLIMITED INTERRUPTIBILITY
CURTAILMENT OPTION != COSTLESS CURTAILMENT
```

## Strongest-owner boundary

Electricity-system planning, grid connections, power-system security, data-centre engineering, planning and industrial policy have much stronger owners.

Ofgem/NESO already explicitly own:
- viability/readiness criteria;
- connection queue curation;
- strategic planning;
- connection timing;
- stress/operational control;
- consumer/system-security trade-offs.

So the project must not present the case as a discovery of grid bottlenecks or flexible load.
