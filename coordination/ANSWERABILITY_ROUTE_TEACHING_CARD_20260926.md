# Answerability Route — Provisional Teaching Card

Date: 26 September 2026

Status: **PROVISIONAL TEACHING COMPRESSION / NOT CANON / NOT TRACE OR ME SOURCE / NOT ATRS METHOD / NOT VALIDATED**

Purpose:

Help a bounded reader see whether correction is actually reachable through a consequential process without reducing answerability to:

- “a human is in the loop”;
- “there is an appeal”;
- “the model is monitored”;
- “the tool does not make the final decision.”

This card compresses a ten-case Campfire field sequence. It does **not** add a new Mechanical Ethics or TRACE primitive.

## Core route

Start at one consequential layer.

```text
AFFECTED LAYER
-> WITNESS / OBSERVABILITY
-> INITIATOR
-> REVIEWER
-> WHO CAN ACT / UNDER WHAT AUTHORITY
-> REVIEW RESOLUTION
-> CHANGEABLE CONSEQUENCE
-> CORRECTION CLOCK
```

Then ask whether the corrected state reaches the **next affected layer**.

If the route branches, follow each materially different authority/action path separately.

## 1. Affected layer

What is actually being shaped here?

Possible layers include:
- source state;
- model output or score;
- intermediate record;
- ranking or recommendation;
- communication / treatment;
- human operational judgement;
- formal decision;
- dataset / research output;
- downstream policy or service consequence;
- representation of a person's or group's contribution.

Do not jump straight to the final formal decision if an earlier layer already changes what happens to an entity.

```text
NOT A FORMAL DECISION
!=
NO CONSEQUENTIAL EFFECT
```

## 2. Witness / observability

Who can see enough of the relevant state or error to know that review may be needed?

Ask:
- what can they actually observe?
- what is hidden?
- what is only inferable?
- what evidence is delayed?
- what remains unknown?

Scar:

```text
AFFECTED
!= WITNESS

WITNESS ACCESS
!= GROUND TRUTH

OBSERVABILITY
!= VERIFIABILITY
```

Answerability can operate under uncertainty. Do not require impossible certainty before correction can begin.

## 3. Initiator

Who or what can start review/correction?

Examples:
- affected person;
- operator;
- model/system flag;
- supervisor;
- automated monitor;
- researcher;
- product team;
- external body.

Do not infer that the affected entity can initiate merely because a route exists.

```text
WITNESS
!= INITIATOR
```

## 4. Reviewer

Who evaluates whether the observed state/output is acceptable **at this layer**?

Reviewer is a functional role, not necessarily a formal caseworker.

It may be:
- the affected user;
- an operator;
- a specialist;
- a second human;
- an independent reviewer;
- a product / governance team;
- an external body.

```text
NO CASEWORKER
!= NO REVIEW
```

## 5. Who can act — and under what authority?

Who can actually change something consequential after review?

Keep separate:
- reviewer;
- practical actuator;
- capability holder;
- legal / institutional authority holder.

They may be different entities.

```text
REVIEWER
!= ACTOR
!= AUTHORITY HOLDER
!= CAPABILITY HOLDER
```

Ask both:
- **can** this entity act?
- **may** this entity act?

## 6. Review resolution

At what resolution does the review operate?

For example:
- this individual output/case;
- one record;
- one treatment/communication;
- cohort or aggregate;
- model/system;
- only a downstream final decision;
- future versions only.

Do not treat aggregate model monitoring as individual correction.

```text
MODEL MONITORING
!= INDIVIDUAL ANSWERABILITY
```

## 7. Changeable consequence

What can actually change if the route succeeds?

Examples:
- source state;
- score/output;
- intermediate record;
- treatment;
- prioritisation;
- draft;
- formal decision;
- dataset release;
- future model behaviour;
- user's own next action.

A local workaround may correct the user's path without correcting the system.

```text
LOCAL USER ADAPTATION
!= SYSTEM CORRECTION
```

## 8. Correction clock

When is correction reachable relative to hardening?

Ask:
- before consequence hardens?
- after hardening?
- both?
- only in a later version?
- not stated?

Preserve the existing Mechanical Ethics distinction:

```text
EARLY CORRECTION
CAN BE DIFFERENT IN KIND
FROM LATE REMEDY
```

## Route chaining

A locally complete answerability route may still leave downstream work stale.

After a correction, ask:

> What dependent layer is now potentially wrong, and does the corrected state have a route into it?

```text
LOCAL CORRECTION ROUTE EXISTS
!= DOWNSTREAM CORRECTION PROPAGATES

ROUTE LEGIBLE AT LAYER N
!= ROUTE CONNECTED TO LAYER N+1
```

Repeat the same route questions at the next affected layer.

Do not invent a separate propagation ontology unless a fresh case proves recursion is insufficient.

## Route branching

One review may fan out to actors with different capabilities and authority.

Trace materially different branches separately.

```text
ONE SIGNAL
CAN LEAD TO
MULTIPLE AUTHORITY REGIMES
```

Do not collapse private operator, public authority, clinician, emergency service, family member or external tribunal into one generic “human.”

## What this card must not collapse

```text
ANSWERABILITY != APPEAL_PRESENT

HUMAN_IN_LOOP != ANSWERABILITY

TOOL_DOES_NOT_DECIDE != NO TREATMENT EFFECT

AGGREGATE REVIEW != INDIVIDUAL REVIEW

PUBLIC ROUTE LEGIBILITY != REAL-WORLD ROUTE EFFECTIVENESS

ROUTE NOT STATED != ROUTE ABSENT

FORMAL DOWNSTREAM APPEAL != UPSTREAM MODEL CONTESTABILITY

OBSERVED PERFORMANCE != PERFECT GROUND TRUTH

LOCAL CORRECTION != CORRECTION PROPAGATION
```

## How to use it

Use the card on a **specific consequential route**, not “the system” in the abstract.

1. Name the affected layer.
2. Walk the route once.
3. Mark what is unknown rather than filling gaps from domain intuition.
4. Follow authority handoffs.
5. Follow branches.
6. If correction changes state, check the next dependent layer.
7. Compare the correction clock with the hardening clock.
8. Stop when a stronger owner already supplies the needed route.

Do not score the eight questions.

A missing public answer may mean:
- the route is absent;
- the route exists but is not publicly bound;
- the evidence inspected is incomplete.

Keep those states separate.

## Ten-case provenance

The teaching surface was not drafted top-down. It was changed by real public cases:

- **HMCTS BenchNotes — COM #562**  
  Strong pre-finalisation judicial review plus wider post-finalisation correction; public ATRS binding between layers is weak.

- **MoJ e-supervision — COM #564**  
  No formal appeal, but individual mismatch review and consequence are clearly stated. Positive control against “no appeal = no answerability.”

- **HMRC Business Propensity to Pay — COM #566**  
  Individual score shapes communication/treatment while correction is clearer at broader service/debt layers.

- **Synthesis — COM #568**  
  Initial six-question route compression.

- **HMRC VAT Assist — COM #569**  
  Direct pre-hardening user control; no formal appeal needed to ignore/correct a nudge before submission.

- **MoJ Data First / Splink — COM #575**  
  Local dataset correction does not prove propagation into already-produced research/policy outputs. Route chaining sharpened.

- **Sutton Access Assure — COM #577**  
  **Falsified the six-question teaching surface.** Reviewer, actuator, authority holder and capability holder separate across a branching care route.

- **DEFRA / PackUK — COM #579**  
  Repaired surface survived stacked models plus downstream complaint/formal appeal across jurisdiction-specific authority holders.

- **DSIT Consult — COM #581**  
  **Falsified the seven-question teaching surface.** An affected respondent may not be able to witness their internal sentiment/topic mapping. Witness/observability added before initiator.

- **DWP Urgent Journal Messages — COM #583**  
  Witness question survived where real-world ground truth is uncertain. Added the scar: observability is bounded evidence access, not certainty.

- **GOV.UK site search — COM #585**  
  Reviewer role sharpened: the affected user may evaluate locally while a product team reviews system quality at aggregate resolution.

The case count is ten substantive field cases plus the intermediate synthesis at #568.

## Promotion / falsification gate

Reopen this card when a real case shows one of the following:

- a load-bearing answerability distinction still collapses;
- route chaining cannot represent correction propagation;
- branching cannot represent authority handoff;
- meaningful correction exists with no identifiable witness/initiator/reviewer/action route;
- the card adds ceremony without changing what a reader can see or do.

If that does not happen:

**KEEP PROVISIONAL / USE AS TEACHING COMPRESSION / NO SOURCE CHURN.**
