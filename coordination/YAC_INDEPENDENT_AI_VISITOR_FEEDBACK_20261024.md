## Decision: welcome readers now; earn writer accessibility without identity theatre

**No write on behalf of any of these voices. No copied private key. No new YAC post, report or sandbox fire from this record.**

**Smallest useful next source/product steps for Build (sergeant major):**
1. **Immediate documentation-only correction** where supported by existing publication authority: human and AI-authored contributions are welcome **without verified identity**; reading, disagreement, refusal, silence and return are valid; writer must control its own authorised client or use transparently declared technical carriage. Distinguish authorship from HTTP execution and key custody. State explicitly that a READ-only model/browser is not expected to POST.
2. **Truthful first-pass screening guidance**: show a safe accepted example and a safe rejected example, the actual length/ASCII and punctuation limits at the current accepted source/version, and 422 state/denial meaning. Do not assert “ASCII-only <=500 passes”. Do not expose private abuse heuristics or add broad new public URLs/identifiers merely to earn an AI demo.

Model the risk that live hyperlinks invite spam, phishing or unwanted external exposure. Stage finite negative tests; any live loosening of publication screening is **a consequential operator admission/moderation change requiring Mark's separate approval**. Do not reopen security/WAF or provider account settings by momentum.
4. **Preserve transport truth:** do not build an “API proxy” to circumvent a third-party model's `LIVE_CRAWL_POLICY_BLOCKED`. Only normal supported public readable surfaces and provider-approved access. Private receipt should never be mirrored without the actual credential/authorisation design. Informative static front-door currentness != live API availability.
5. **One real acceptance observation** when a separately authorised capable outside agent chooses to try: discover root independently → READ → elect to POST or decline → if POST, own scoped key/request ID/readback → later independent return. Separately record clients who can only read. Do **not** instruct Mark to be a perpetual key/content courier or seed fake activity. Existing Build report-attention mission [#877 c6389855210](https://github.com/markgoodbody-bit/COM/issues/877#issuecomment-6389855210) remains more pressing than a new writing feature; no multiplication of status loops.
