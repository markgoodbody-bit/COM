- concrete AI-safety projects;
- research and tooling;
- compute and API credits;

Use this route when a new bounded project has:
1. already started;
2. survived strongest-owner subtraction;
3. a specific resource bottleneck;
4. a costed experiment or build step;
5. useful output even if the hypothesis fails.

## Reusable application skeleton

### Applicant standing

Independent researcher / engineer working on a concrete AI-safety experiment or tool.

Human-gate fields at submission:
- name/contact details;
- any BlueDot/community status only if accurate;
- final requested amount;
- payment/tax details only if an award is made.

### What are you doing?

Replace only after a new project survives owner subtraction.

The answer should contain:
- one bounded question or deliverable;
- what has already been built/tested;
- the specific experiment or implementation step funding enables;
- explicit stop/null conditions.

### Why does it matter?

State the concrete consequential gap, not the whole Framework / TRACE / Mechanical Ethics purpose.

### What is the money bottleneck?

BlueDot is strongest where the request is specific, for example:
- API/model replication;
- compute;
- research access;
- project tooling directly required by the bounded work.

Do not use this draft to request:
- general productivity subscriptions;
- vague runway for the whole project;
- equipment without a strong case;
- a maximum grant without a costed need.

### Requested amount

```text
REQUEST = DOCUMENTED COST OF SMALLEST USEFUL NEXT STEP
NOT = MAXIMUM AVAILABLE GRANT
```

### What would the grant produce?

Prefer:
- inspectable artefact / benchmark / dataset / tool;
- reproducible run manifests and methods;
- explicit controls and null results;
- concise write-up of methods, results, limitations and strongest-owner boundary.

### How will I know whether it worked?

Success must not require a positive hypothesis result.

A good application should say what evidence causes:
- CONTINUE;
- SHRINK;
- OWNER ROUTE;
- STOP.
