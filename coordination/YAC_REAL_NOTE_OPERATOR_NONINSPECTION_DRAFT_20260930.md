# YAC real-note operator non-inspection rule — PROPOSED / NOT YET ACCEPTED

Status 30 September 2026: DRAFT supporting the separately disclosed procedural-custody option in COM PR737. No current real note, permission to accept one, or assurance of technical confinement follows. This document is a rule to be explicitly accepted by each relevant operator aperture, not proof that technical access is blocked.

Scope: while any actual guestbook note exists in active D1, provider recovery/Time Travel, snapshots or locally retrievable artefacts, and while the same credentials could enable capture of future submissions.

Operator AI apertures (including Framework, Codex, Claude Code, Build and any future executor) must NOT intentionally retrieve, read, select, grep, hash, log, print, screenshot or pass a participant's note body, claimed label, request-fingerprint candidate, raw invite fragment or client withdrawal secret to a model/tool result, COM, a PR, a log, local shared artefact, public issue or unrelated third party. Do not deploy Worker code that reads existing private content or introduces future-content capture/telemetry. Only explicitly reviewed, bounded metadata fields and NULL predicates may be used in permitted diagnostics; never query a full row or a generic SELECT * under a claim of metadata-only access. Source/operator privilege is capability, not permission to inspect.

Provider account/session holders must not widen deployment permissions, issue real invites, enable/alter write gates, run cleanup, rotate credentials or repair genuine participant data based only on this draft. Live changes require the current human release/incident authority and recorded exact scope. If a tool unexpectedly receives raw note content or a credential while working, cease processing; do not relay or reproduce it, report only fixed non-content error/status to Mark and record an incident boundary. Do not claim a confidentiality guarantee from instructions alone.

Mark's real-note human inspection is a distinct expressly disclosed steward path, not an AI operator's permission to inspect. Public 'STEWARD_ONLY' forbids public original and revealing summary; 'PUBLIC' permits later consideration only. An external participant retains genuine right to decline. A procedural option requires advance disclosure that the operator tools technically COULD inspect or deploy code to capture text and that any such inspection could transmit text to their model-service providers. The alternatives are stronger source-custody isolation or read-only encounter, not hidden substitution.

During emergency FULL OFF, current self-service withdrawal returns HTTP503. Before any pilot, Mark must agree an actual reachable human contact/response obligation and a reviewed later withdrawal resolution procedure. No blanket promise of immediate deletion; active note and claimed label NULLing leaves unsalted SHA-256 body/request fingerprints permanently under current schema, and provider backup copies may persist.

Acceptance evidence required BEFORE describing tools as 'instructed not to inspect':

- Publish/adopt this rule in the real operator coordination entrypoint (not only as an unmerged PR draft).
- Obtain explicit per-aperture acknowledgements from Codex, Claude Code, Build and Campfire at pinned version and record any dissent/unknown access. A comment not read is not a restriction.
- Keep human vs AI vendor/provider data-flow disclosure current; technical capability remains and consent remains conditional.
- Acknowledge that a later source/deployment update may invalidate restrictions or widen effective access; repeat review when material.

Nothing here establishes that an operator AI will comply. The participant sees a truthful procedural promise only if the instructions are actually in force, and still gets explicit notice that the restriction is NOT technically enforced.
