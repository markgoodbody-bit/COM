## Draft — brief description of the project

The Human Record is a public, human- and machine-readable project for preserving evidence lineage, source ancestry, uncertainty and correction history without turning a record into a truth oracle. Each record keeps the underlying sources and observations inspectable, separates names from entities and URLs from sources, preserves unresolved questions, and derives readable human views from the same underlying record state. The repository currently includes three deliberately different public records, an incremental identity/source registry, a deterministic integrity validator, GitHub CI, public contribution/correction routes, and continuation instructions. Project-authored rights held by the maintainer are dedicated under CC0 1.0, with third-party rights kept explicitly separate.

## Draft — how API credits would be used

API credits would support bounded, reproducible work that improves The Human Record without turning model output into authority. Intended uses include:

1. **Provenance and evidence-lineage stress testing** — test how current models handle repeated, derivative, contradictory, corrected and incomplete evidence, with frozen inputs, null controls and explicit uncertainty rather than treating model agreement as truth.
2. **Record maintenance and correction tooling** — assist with source/currentness checks, proposition-drift detection, alias/source-relation reconciliation and regeneration of human-readable views, while deterministic validation remains the release gate.
3. **Machine-reader robustness** — test whether records remain legible to current models when source relationships, identity ambiguity and unknowns are presented in machine-readable form, and preserve negative/inconclusive results.
4. **Codex-assisted open maintenance** — use Codex for bounded implementation, test generation, hostile review, documentation and pull-request maintenance of the public repository.
5. **Reproducible evaluation artefacts** — preserve prompts, model/runtime identity, usage/cost evidence, exact inputs and result ceilings so later humans or artificial systems can inspect what was actually tested.

The credits would replace real project/API expenditure and allow broader controlled testing than the maintainer can reasonably subsidise personally. They would not confer governance authority on OpenAI models or be used to manufacture claims of validation.

## Draft — additional information

The project is intentionally small and falsifiable rather than a universal database or certification system. Its current three records cover artwork provenance, the ancestry of a viral historical claim, and public-source transmission lineage around a living craft practice. The architecture preserves distinctions such as `URL != SOURCE`, `OBSERVATION != PRESERVED COPY`, `UNKNOWN != ABSENT`, and `HUMAN VIEW != RECORD STATE`.

The wider project has also produced a bounded provenance-mutation experiment for AI evidence handling. That work is useful as a test source, but this Fund application should remain anchored to The Human Record itself unless the form or reviewer explicitly asks for related work.
