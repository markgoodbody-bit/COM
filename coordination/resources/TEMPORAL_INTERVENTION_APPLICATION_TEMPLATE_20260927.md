# Temporal intervention — bounded application template

Date: 27 September 2026

Status: **WORKING TEMPLATE / NOT CANON**

Use only after a real operating system / public case exists.

## 1. World / real use

What actually happened or is operating?

Source:
- owner/public evidence;
- date/currentness;
- population/scope.

## 2. Strongest owner

Who already owns:
- the domain;
- the duty;
- the process;
- the timing rule;
- the intervention method?

## 3. Existing temporal protection

Before proposing anything, list what the system already does:

- notice;
- next-check date;
- deadline;
- reminder;
- pause/tolling;
- schedule control;
- workload reduction;
- escalation;
- fallback;
- named action holder;
- recovery/rest protection.

~~~text
PATTERN PRESENT
!=
GAP
~~~

## 4. Specific consequential residue

What remains after owner subtraction?

Keep separate:
- backend state;
- affected-entity visibility;
- timing control;
- work imposed;
- uncertainty;
- parallel clocks;
- hardening;
- irrecoverable loss.

## 5. Smallest help

Prefer one of:

~~~text
REMOVE WORK
NAME OWNER
SHOW NEXT CHECK
REPRESENT UNCERTAINTY
ADD CUE
ALLOW DEFERRAL
PROTECT PARALLEL ROUTE
MOVE TEMPORAL RISK
MAKE WAIT CONSEQUENCE VISIBLE
~~~

Do not default to "build another system."

## 6. Burden test

Who must now:
- remember;
- monitor;
- fill forms;
- chase;
- coordinate;
- wait;
- recover;
- explain?

~~~text
HELP ADDED
!=
BURDEN REDUCED
~~~

## 7. Power / control test

Who can:
- set the deadline;
- change it;
- wait cheaply;
- accelerate;
- pause;
- demand evidence;
- make the other party synchronize?

## 8. Anti-normalisation test

Ask:

> Is the intervention helping the affected entity, or mainly making them conform more reliably to the operator's preferred rhythm?

## 9. Domain-safety check

What specialist owner must approve before this becomes real guidance?

Examples:
- clinician;
- lawyer;
- educator;
- regulator;
- scheduler/human-factors owner;
- accessibility/disability owner.

## 10. Kill / route condition

State what would make this:

- OWNER FOUND / NO DELTA;
- NOT OUR GAP;
- TOO BURDENSOME;
- UNSAFE;
- INSUFFICIENT EVIDENCE;
- PROCEED TO SMALL REVERSIBLE TEST.

## 11. Consequence watch

If ever implemented, what would we watch?

Not only throughput.

Possible measures:
- extra work removed/created;
- chasing contacts;
- missed windows;
- wait uncertainty;
- sleep/recovery burden;
- route closure;
- false alerts;
- operator workload;
- inequitable access;
- unintended delay elsewhere.

## Guard

~~~text
FASTER != BETTER BY DEFAULT
SLOWER != WORSE BY DEFAULT
VISIBLE WAIT != ACCEPTABLE WAIT
REMINDER != AUTHORITY
FLEXIBILITY != TEMPORAL AGENCY
OWNER FOUND != PROJECT FAILURE
~~~
