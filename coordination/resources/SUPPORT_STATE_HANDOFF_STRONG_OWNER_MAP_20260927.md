## 1. Personal Communication Passports — strong prior owner

CALL Scotland's Personal Communication Passports date to 1991.

Owner surfaces:
- https://www.communicationpassports.org.uk/about/
- https://www.communicationpassports.org.uk/
- https://www.communicationpassports.org.uk/creating-passports/good-practice/

The owner describes passports as useful for transitions between settings/services, multi-agency collaboration, people meeting many professionals/support staff, and avoiding the need to tell the same story repeatedly. The passport is intentionally personal rather than a generic off-the-shelf profile.

~~~text

!=
PROJECT NOVELTY
~~~

## 2. NHS Accessible Information Standard — strong operational owner

Current NHS England Accessible Information Standard requires health/adult-social-care organisations to identify, record, flag, share, meet and review information/communication support needs.

Owner surfaces:
- https://www.england.nhs.uk/long-read/accessible-information-standard-requirements-dapb1605/
- https://www.england.nhs.uk/long-read/accessible-information-standard-implementation-guidance/

The standard explicitly carries needs through treatment, ongoing care, referral, discharge and handover. It recognizes communication/health passports as useful supplements while requiring accurate organisational records, regular review/currentness, and flags/alerts that prompt action.

~~~text
IDENTIFY -> RECORD -> FLAG -> SHARE -> MEET -> REVIEW
= STRONG OWNER PIPELINE

HANDOFF SUPPORT STATE
!=
UNOWNED HEALTHCARE PROBLEM
~~~

## 3. NICE — avoid repeated disclosure

NICE guidance recommends asking whether an up-to-date communication passport exists and recording communication preferences in a shareable form so relevant services can use them without requiring repetition.

Owner surfaces:
- https://www.nice.org.uk/guidance/ng213/chapter/recommendations-on-support-for-all-disabled-children-and-young-people-with-severe-complex-needs
- https://www.nice.org.uk/guidance/ng213/evidence/b-involving-children-and-young-people-pdf-11006670063

~~~text
UP-TO-DATE SUPPORT PREFERENCES
+ SHARE WITH RELEVANT SERVICES
+ REDUCE REPEATED DISCLOSURE
= OWNER FOUND
~~~

## 4. Real implementation lesson — profile existence is not profile use

A communication-passport study in an eating-disorder service reports passports completed with clinical teams, uploaded to the electronic clinical record and made accessible to the care team. It also discusses prior implementations where passports were not consistently recognized/reviewed or staff awareness was weak.

Owner surface:
https://pmc.ncbi.nlm.nih.gov/articles/PMC11876190/

~~~text
PROFILE CREATED != PROFILE AVAILABLE
PROFILE AVAILABLE != PROFILE READ
PROFILE READ != SUPPORT APPLIED
SUPPORT APPLIED ONCE != SUPPORT CURRENT LATER
~~~

This fits the existing project conformance work rather than creating a new theory.

## 6. Stronger-owner subtraction

The provisional object should no longer be described as a portable profile for carrying support/vulnerability needs across channels or services. Mature owners already cover that function.

The remaining cross-domain residue, if useful, is narrower:

> At a consequential handoff, preserve the minimum action-relevant route state plus any already-owner-defined support adjustment needed for the next legitimate step, with explicit source/currentness/access boundaries.

This is a **handoff receipt**, not a person profile.

## 7. Why the route-state portion may still be useful

Communication passports/accessibility standards primarily own communication needs, access preferences, support adjustments and person-centred contextual information.

The project receipt also joins current issue/route state, completed actions, next action holder, next action, next check/deadline, the minimum owner-defined support adjustment, and currentness/provenance/access limits.

The claim is not that these fields are novel individually.

~~~text
PROCESS / ROUTE CONTINUITY
+ MINIMUM SUPPORT CONTINUITY
+ CURRENTNESS / ACCESS BOUNDARY
= DESIGN COMPRESSION ONLY
~~~

## 9. Privacy / ownership correction

~~~text
PROFILE PORTABLE != PROFILE PUBLIC
SHARED WITH RELEVANT SERVICE != SHARED WITH EVERY SERVICE
PERSON-CENTRED != INSTITUTION-OWNED IDENTITY GRAPH
TELL US ONCE != TELL EVERYONE EVERYTHING
~~~

Stronger owners must determine lawful basis, consent/permission where applicable, minimum necessary data, recipient scope, retention, correction/update, withdrawal/revocation where applicable, and security.
