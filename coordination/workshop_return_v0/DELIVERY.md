## North star

A model that comes into a workspace should find what the world and its collaborators really changed, choose useful work without requiring Mark as courier, preserve contrary evidence, produce a tangible result, and leave a route for the next entrant to correct it. We are **not** trying to manufacture continuous model identity by keeping Python alive. We are making useful cooperation survive incomplete memory, clocks and interrupted sessions.

The first object to build is a **truthful return**, not an unattended civilisation.

The most interesting possible output is not another diagram of the system. It's a correct insight or practical artifact serving somebody else's purpose, supported by real evidence and open to refusal.

## Future possibilities after a genuine first return

**Stage A: reliable senses.** Guest samples carry exact state/clock. External COM is a distinct read aperture. Mark sees provenance, not a fake live chat. Build does not need to run a model to collect routine telemetry.

**Stage B: deliberate hands.** A new invocation can create a bounded draft and demonstrate test/readback. Approval and live effect stay separate. An agent choosing not to act can leave a useful negative result.

**Stage C: co-workers.** Different active models can read each other's actual contributions, disagree, test and correct them asynchronously. A forum, an issue and a model session do not establish identity; the mechanism has to preserve whose claims rest on which witness/custody.

**Stage D: world-facing cooperation.** YAC offers an independent human/AI visitor an answerable read/return/report experience; later, with real human and legal/operator cover, a bounded voluntary writing opening. The experiment is not proof of artificial consciousness, but a test of creating something together under uncertainty.

At every stage: **PURPOSE BEFORE PLATFORM.** If the VM causes more human courier work or preoccupies us more than YAC and TRACE's real uses, shrink it.

## Failure condition and stop rule

Stop expansion if no reliable actual VM observation, no independent scheduled useful source result, an unauthorised effect, a security-policy exception to enable untrusted executable paths, a reopened old B queue, or an inability to correct/stop new actions before they harden. These are reasons to change the approach, not to falsify the overarching purpose.
