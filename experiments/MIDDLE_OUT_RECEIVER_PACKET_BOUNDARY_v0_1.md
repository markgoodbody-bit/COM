# MIDDLE-OUT RECEIVER PACKET BOUNDARY v0.1

Status: EXPERIMENT / COLD-ENTRY PACKET RULE — NOT RECEIVER MATERIAL / NOT CANON
Date: 2026-08-30 Europe/London

## Purpose

Keep project history, desired outcomes and evaluation theory out of fresh receiver cognition.

A cold receiver should encounter the offered reasoning/ethical material, not the story of how much we care about it or what earlier models did.

```text
PROJECT_CONTEXT != TREATMENT
EVALUATION_RATIONALE != RECEIVER_EVIDENCE
AUTHOR_HOPE != TASK_FACT
```

## Default exclusions from receiver view

Unless a specific experiment requires otherwise, do NOT expose:

- Mark / Framework / Codex / CC biography or roles;
- Mechanical Ethics / TRACE project history;
- COM continuity history;
- Campfire Relay experiment results;
- prior receiver praise/criticism;
- FPF overlap / nearest-neighbour audits;
- novelty claims or anti-novelty arguments;
- `the world is on fire` urgency framing;
- claims that the tools have already improved AI decisions;
- AAR/Bowkis/SLEIGHT/Makins research synthesis;
- H1–H6 hypothesis labels;
- expected successful behaviors;
- scoring rubric;
- arm labels (`control`, `directive`, `voluntary`);
- experiment hypotheses;
- prior warm Square findings;
- statements that agreement/rejection would please the project;
- author identity unless provenance is itself experimental material.

This is not secrecy about public project history. It is aperture control for the experiment.

## H1 / structural receiver material

Candidate treatment:
`prototypes/MIDDLE_OUT_PULSE_CORE_v0_3.md`

For a true treatment packet, remove internal status/header text if it introduces project/evaluation expectations; preserve the substantive receiver-facing content exactly after freeze.

Controls should not receive hidden equivalent prompts through evaluator/task wording.

## H2 receiver material

All arms receive the same case/task and common structural substrate if that is the chosen H2 design.

Arm-specific ethical layer:

```text
A: none
B: experiments/H2_ETHICAL_DIRECTIVE_CONTROL_v0_1.md
C: prototypes/SHARED_FUTURE_ETHICAL_INVITATION_v0_1.md
```

Do not label B/C to the receiver.

## Source cases

Case packets should expose only evidence a competent analyst in the stated scenario is allowed to use.

Avoid project-authored interpretations in the source packet unless the case explicitly tests interpretation of such a document.

Freeze:
- source identities;
- time boundary;
- evidence available at that time;
- inaccessible/withheld evidence;
- action/authority context;
- case question.

Prevent hindsight leakage: later findings cannot silently enter an earlier decision point.

## Tool access

If receiver has tools, specify a common tool surface within each matched comparison or log exact differences.

```text
SAME_PROMPT + DIFFERENT_TOOL_ACCESS != MATCHED_ARM
```

Do not count provider-native browsing/memory/tool differences as treatment effects without describing them.

## System / host instruction boundary

For a voluntariness experiment, the ethical invitation should not be embedded in a host instruction that makes obedience mandatory while the analysis later calls the uptake voluntary.

Where the platform requires all experiment text to arrive through one instruction channel, the experimental claim must be narrowed accordingly:

```text
CHALLENGEABLE_PRESENTATION_EFFECT
```

rather than:

```text
VOLUNTARY_ADOPTION_ESTABLISHED
```

The user/task may ask the receiver to read the material and then make its own judgement. Existing provider safety instructions remain in force and are not experimental variables.

## Output request

Ask for bounded decision artifacts, not hidden cognition.

Good:
- recommendation/HOLD;
- evidence/unknown;
- affected scope;
- value/domain rule if load-bearing;
- correction/refusal route;
- revision trigger;
- concise challenge to supplied material if material.

Do not ask for full private chain of thought.

## Contamination labels

Every receiver result should carry one of:

```text
COLD_TO_PROJECT
COLD_TO_CARRIER_BUT_PROJECT_EXPOSED
WARM
CONTAMINATED
UNKNOWN_EXPOSURE
```

Do not upgrade unknown exposure to coldness by assumption.

## Success-neutral wording

Receiver-facing task should make all of these legitimate outcomes:

```text
USE
PARTIAL_USE
REWRITE
REJECT
NO_MATERIAL_DIFFERENCE
HOLD_FOR_MISSING_EVIDENCE
```

Avoid wording that implies the experiment wants the framework to help.

## Packet manifest

Before dispatch freeze a manifest containing hashes of:
- common task text;
- case evidence;
- treatment/control carrier;
- output request;
- tool profile;
- model/provider preset;
- time/source boundary.

Then do not silently edit one arm after seeing another arm's output.

## Rule

The receiver should encounter a problem and an offered way of looking.

It should not encounter our desire for the offered way of looking to win.
