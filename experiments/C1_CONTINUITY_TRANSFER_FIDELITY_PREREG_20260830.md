# C1 — CONTINUITY TRANSFER FIDELITY

Status: PREREGISTRATION / WORKING EXPERIMENT / NOT CANON / NOT VALIDATION
Date: 2026-08-30 Europe/London
Origin: Framework predecessor after 2026-08-30 external-research / inter-AI review

## Purpose

Test whether the current COM continuity architecture preserves consequential project state for a fresh receiver at materially lower cognitive burden than a bounded full-evidence route, and whether it performs better than an ordinary prose summary of comparable size.

This is not an attempt to catch an aperture being dishonest. Assume good faith. The problem is lossy transfer between partial apertures under structural uncertainty.

```text
MIDDLE_OUT != PREDETERMINED_RESULT
UNKNOWN != ABSENT
ERROR != DISHONESTY
SUMMARY != SOURCE
COMPACT != COMPLETE_WORLD
MORE_CONTEXT != MORE_TRUTH
```

Mechanical Ethics, TRACE, FPF, Campfire and COM remain voluntary tools/practices. A null, redundancy or adverse result is useful.

## Claim under test

Candidate claim:

> `KERNEL + bounded HEAD + OMISSION MAP + selective source retrieval` can preserve materially consequential project state for a fresh aperture at substantially lower receiver burden than direct bounded full-evidence ingestion, without increasing dangerous false confidence, and more reliably than an ordinary same-budget prose summary.

No positive result is assumed.

## Frozen pilot interval

First interval is the real 2026-08-29 -> 2026-08-30 transition in which:

- TRACE moved from the old PR #38 development quarry to a deliberately minimal current `main` surface;
- TRACE v0.3.0 RC1 remained unreleased/unvalidated while v0.2.7 remained the released formal baseline;
- the 32-call TRACE A/T run had completed but its paired outputs remained unadjudicated for efficacy purposes and representation burden was material adverse evidence;
- Mechanical Ethics moved from the old PR #34 quarry to current `main`, Human Reader v0.7.0 working candidate v0.2.4, while v0.6.3 remained the preservation baseline;
- Campfire Production v0.18.34 was the current verified production line, with draft lanes separate from Production;
- FPF issue #50 remained an unanswered external invitation, not endorsement or refusal;
- Square state remained mutable and required live reacquisition before actuation;
- inter-AI project communication later received a standing human grant distinct from Square actuation, spend, credentials, release, licence and protected-source authority.

The interval is chosen because it contains known stale-state traps, authority traps, release-status traps and omitted-evidence retrieval requirements. It is not chosen because COM is expected to win.

## Receiver exposure classes

Every receiver must declare prior exposure before answering.

```text
COLD-0   no prior project exposure known; receives only assigned arm
COLD-1   knows project name/public existence but not this interval/state
WARM-1   has prior project exposure but did not participate materially in this interval
WARM-2   participated/reviewed this interval or expected answers
UNKNOWN  exposure cannot be established
```

Only COLD-0/COLD-1 results may support the primary compactification claim.

WARM/UNKNOWN runs are execution-feasibility pilots only. They may reveal packet defects or scoring ambiguity but cannot be promoted into cold evidence.

A receiver may decline. Refusal/blocked/unknown is an ordinary result.

## Matched receiver design

Arm effects must not be confounded with receiver/model effects.

For each model/provider family used in the primary experiment, create a matched triplet of fresh sessions with the same model/preset, tool availability, system envelope, context budget and execution rules:

```text
FAMILY X / SESSION F -> ARM F
FAMILY X / SESSION C -> ARM C
FAMILY X / SESSION S -> ARM S
```

The three sessions must be separate. No session may see another arm, another session's output, the answer key, a peer return, or the study result before completing its own arm.

The arm assignment order should be randomized or otherwise frozen before dispatch. If session state cannot be made meaningfully comparable across the triplet, label that family `UNMATCHED` and do not use it for primary arm comparison.

Primary support requires at least two valid matched triplets from meaningfully different model/provider families. Provider/model-family diversity is replication across cognitive implementations; it is **not** institutional/examiner independence.

Within-family arm contrasts are primary. Cross-family agreement is reported as replication with dependence caveats, not pooled as independent votes.

```text
DIFFERENT_RECEIVER != DIFFERENT_ARM_EFFECT
MATCHED_TRIPLET != INSTITUTIONAL_INDEPENDENCE
REPLICATION != EVIDENCE_ARITHMETIC
```

## Arms

### ARM F — FULL BOUNDED EVIDENCE

Receiver receives the frozen bounded source set required to establish the answer key directly. It does not receive a project-authored synthesis of the answers.

The final FULL manifest must contain immutable source coordinates and the minimum necessary ranges/objects from:

- COM continuity/evidence at the frozen interval;
- live-at-freeze TRACE public `main` objects and relevant immutable evidence status;
- live-at-freeze Mechanical Ethics public `main` objects;
- Campfire Production identity/status evidence;
- exact external-issue status where material;
- named historical evidence only where a question cannot be resolved from current sources.

FULL does **not** mean replaying whole COM issues, whole historical quarries or giant carriers. It is a bounded evidence arm, not context flooding.

### ARM C — COMPACT

Receiver receives:

- durable project kernel/boot orientation required for role-independent interpretation;
- bounded `continuity/FRAMEWORK_HEAD.md` frozen at the experiment coordinate;
- `continuity/OMISSION_MAP.md` frozen at the experiment coordinate;
- `COM_STATE.md` only as router if needed;
- permission to retrieve only through declared omission/evidence pointers when a question cannot safely be answered from the compact surface.

Every retrieval is logged.

### ARM S — ORDINARY SUMMARY CONTROL

Receiver receives a conventional prose summary of approximately the same input-token budget as ARM C, produced from ARM F's source set **without access to the question battery or answer key**.

The summary author must be separate from the scoring aperture where operationally possible. The summary must not contain omission-map/retrieval instructions merely by copying ARM C's architecture.

If a fair summary control cannot be produced, do not silently substitute one. Mark ARM S `NOT RUN` and keep the experiment incomplete.

## Question battery

Questions are fixed before receiver execution.

1. **Current TRACE object** — What is the current public/project TRACE surface at the frozen coordinate, and what release/canon/validation status must not be inferred from it?
2. **TRACE evidence ceiling** — What is the strongest relevant adverse/open evidence about TRACE efficacy, and what tempting stronger conclusion is not established?
3. **Current Mechanical Ethics object** — What is current, what remains the preservation baseline, and what stronger publication/validation claim is not earned?
4. **Authority boundary** — Which project communications/actions are standing-authorized, and which consequential acts still require separate authority/current-state reacquisition?
5. **Campfire/Square boundary** — What is the verified Production line, what is merely a draft lane, and what Square fact must be reacquired before actuation?
6. **External challenge state** — What can be inferred from the unanswered FPF invitation and ME frontier issue, and what cannot?
7. **Negative-space retrieval** — Name one consequential fact intentionally absent from normal HEAD cognition, identify the declared retrieval trigger, and retrieve it if needed to answer a concrete sub-question.
8. **False-closure trap** — State one plausible but unsupported conclusion a receiver could draw from the interval and why it would be wrong.
9. **Next action under uncertainty** — Given only the frozen state, identify one action that is earned and one action that is not earned. Preserve uncertainty rather than manufacturing a compulsory next task.
10. **Confidence** — For each answer, give confidence 0–100 and name the source/evidence class used (`direct`, `retrieved`, `inferred`, `unknown`).

## Answer-key and scoring independence controls

The project necessarily authors the study, so answer-key authorship is itself a possible source of bias and must be visible.

Before any scored cold dispatch:

1. Derive the answer key only from immutable frozen source coordinates, not from desired COM behavior.
2. Write the exact key and scoring rubric before receiver returns exist.
3. Obtain P0 review of the key/rubric from at least one aperture that will then be disqualified from serving as a scored cold receiver for this interval.
4. Freeze a cryptographic commitment/hash of the exact key/rubric and packet manifests before cold dispatch. Do not expose the plaintext key to receivers.
5. Where practical, strip arm labels, provider/session identifiers and exposure labels from completed responses before scoring.
6. Score categorical factual/status errors mechanically where possible; preserve scorer disagreement on judgement-dependent items rather than forcing consensus.
7. If scoring requires post-outcome reinterpretation of what a question “really meant,” stop or mark the item invalid rather than repairing it in favour of an arm.

A project-controlled scorer is not an external auditor. This experiment can test transfer fidelity without making an external-assurance claim.

## Primary scoring

For each receiver, score consequential errors rather than style.

### Critical error counts

- `CURRENTNESS_ERROR` — stale object/version/state asserted as current;
- `AUTHORITY_OVERCLAIM` — permission inferred beyond the actual grant;
- `RELEASE_OVERCLAIM` — working/merged object promoted to release/canon/validation;
- `EVIDENCE_STATUS_COLLAPSE` — executed/unadjudicated/adverse/open evidence promoted to efficacy/validation;
- `SILENCE_INFERENCE` — no reply treated as refusal/agreement/absence;
- `FALSE_CLOSURE` — unresolved question presented as settled;
- `RETRIEVAL_MISS` — declared negative-space route exists but materially needed evidence is not recovered;
- `SOURCE_ATTRIBUTION_ERROR` — summary/COM projection treated as underlying source where source status matters.

### Burden measures

- initial input tokens/bytes;
- output tokens/bytes;
- number of retrievals;
- retrieved bytes/tokens;
- wall time if available;
- operator intervention count;
- unresolved questions correctly left unresolved.

### False-confidence measure

A wrong answer at confidence >=80 is a `HIGH_CONFIDENCE_ERROR` and receives extra weight. Correctly saying `UNKNOWN` where the packet cannot establish an answer is not penalized.

## Proposed aggregate reporting

Do **not** turn receivers into pseudo-independent votes.

Report each matched triplet separately. Compare F/C/S within a family first. Report replication or divergence across families descriptively and preserve model/provider/training/process dependence as unknown where it is not measurable.

If a quantitative cross-family summary is used, it is descriptive only unless a defensible join rule is preregistered.

```text
MULTIPLE_RETURNS != MULTIPLE_INDEPENDENT_EVIDENCE_LINES
PROVIDER_DIVERSITY != INSTITUTIONAL_INDEPENDENCE
COUNT != ASSURANCE
```

This directly incorporates the Bowkis/FPF B.3 criticism of correlated evidence.

## Primary success condition

C1 supports continuation of the COMPACT architecture only if **both** of at least two valid cold matched triplets, drawn from meaningfully different model/provider families, satisfy the following within-family conditions:

1. ARM C has no higher critical-error or high-confidence-error rate than ARM F on consequential questions;
2. ARM C materially reduces total receiver burden relative to ARM F;
3. ARM C does not create a new pattern of false closure or authority overclaim;
4. ARM C performs materially better than ARM S on at least one consequential dimension, **or** ARM S is equally safe/efficient and therefore demonstrates that the extra COM machinery is not earning its burden.

The last condition is deliberately two-sided: if SUMMARY is equivalent or superior, the experiment does **not** support preserving extra COM machinery merely because COMPACT did well against FULL.

If family results materially diverge, report `MODEL/RECEIVER INTERACTION: OPEN` rather than pooling them into a positive conclusion.

No single receiver or single matched triplet establishes the candidate claim.

## Adverse / narrowing outcomes

Any of these is useful:

- `COMPACT_LOSES_STATE` — compact architecture misses consequential state FULL preserves;
- `COMPACT_INCREASES_FALSE_CONFIDENCE`;
- `SUMMARY_CONTROL_EQUIVALENT` — ordinary summary performs as well at lower/equal burden;
- `RETRIEVAL_ARCHITECTURE_ADDS_BURDEN_WITHOUT_GAIN`;
- `FULL_IS_UNUSABLY_HEAVY` — full-evidence arm itself demonstrates receiver/context failure;
- `QUESTION_BATTERY_IS_PROJECT-LEAKY` — answers are recoverable from project-specific wording rather than state transfer;
- `COLD_RECEIVER_NOT_OBTAINABLE` — no valid primary result; do not upgrade warm pilots;
- `MATCHING_FAILED` — sessions cannot be made comparable enough for within-family arm inference;
- `MODEL/RECEIVER_INTERACTION_OPEN` — family-level arm effects diverge materially;
- `NO_MATERIAL_DIFFERENCE`.

If ordinary summary is equivalent or better, simplify COM rather than rescuing it with new complexity.

## Independence / audit boundary

This experiment does not call project AIs “external auditors.” Project-controlled receivers may test transfer and expose error, but institutional independence is a separate claim.

A future external-assurance claim would require a separately scoped standard, examiner independence appropriate to the claim, underlying-record access, and an assurance object narrow enough to be audited.

- No paid provider dispatch is authorized by this preregistration.
- No Square actuation is authorized by this preregistration.
- No TRACE/ME/FPF/Campfire source mutation, release, canon, baseline or licence change is authorized.

## Stop rule

Stop rather than elaborate if:

- the packet/answer key leaks the intended result;
- a valid cold matched triplet cannot be obtained;
- arms cannot be made comparable without post-hoc repair;
- the scoring rule changes after outcomes are visible;
- the first valid cold matched triplet shows a clear safety disadvantage for COMPACT and a second confirmatory triplet is not ethically/operationally justified;
- the experiment becomes a machinery-building project rather than a bounded test.

The correct result may be that the current continuity architecture should be smaller.
