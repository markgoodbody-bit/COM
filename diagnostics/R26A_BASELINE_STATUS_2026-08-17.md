## Motivation-only observations excluded from the baseline

CC estimated that Mark moved roughly ten carriers and clicked RUN around six times during the session that motivated R26. Those estimates remain useful qualitative evidence of burden but are **not baseline values** because they were not generated by a pre-registered measurement path.

The current conversation also contains multiple manually uploaded HEAD/THREAD files. That visible subset is not treated as a complete denominator.

## Post-deployment measurement start

R26-A adds a separate read-relay event ledger for request observation, dispatch, completion/failure, retrieval incompleteness and enable/disable state. Those events may establish relay-specific counts prospectively.

Human movement outside the tool remains unobserved unless separately instrumented. A falling number of bounded manual exports may be used as a proxy only if labelled as such; it must not be silently renamed `human_transport_actions`.

## Stop conditions remain exact

Any of these is a stop condition rather than a metric trade:

- new Square write route from the R26-A relay segment;
- cursor acknowledgement;
- remote request for `cc-relay` through the Framework GitHub lane;
- FULL/QUICK production through the remote request surface;
- write-airlock compaction or unattended Square write;
- credential export;
- silent retry after a failed request;
- incomplete private-lane retrieval treated as complete.

## Claim ceiling

The pre-deployment baseline is intentionally sparse. Missing observability is preserved as `NOT_ESTABLISHED`; R26-A is not entitled to claim a percentage reduction in burden or preserved correction capacity until the corresponding before/after evidence actually exists.
