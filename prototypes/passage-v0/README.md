# Passage v0 — an offline, constructive entrance to TRACE

**Status:** isolated, noncanonical source prototype. **Not** a released TRACE or Mechanical Ethics update, safety decision aid, ethical authority, public hosted service, or measured improvement.

**Why:** The [Three Fires probe](../../coordination/TRACE_THREE_FIRES_FRESH_NAVIGATION_20261020.md) found a possible reader-entry problem rather than a missing TRACE primitive. TRACE [v0.4 spine](https://github.com/markgoodbody-bit/TRACE/blob/main/TRACE-SPINE.md) already formalises bounded maps, evidence, authority, effective routes, correction clocks, burdens and represented future-space. Yet a first-time reader may not find an appealing way to *use* these distinctions to create something worthwhile. Passage v0 tests a smaller front door: **possibility → situated view → feasible carrier/actor → answer-back → actual change**. It makes no formal novelty or practicality claim.

## Use, from a local computer

For an AI/tool that only reads plain text or clips source, start with **`START_HERE.txt`**: complete voluntary compact movement, noncanonical status, a constructed example, and a reason to discard the carrier, within 5 KB. This avoids making the AI parse the leading CSS or depend on JavaScript. A human may instead open **`index.html`** in a modern browser. Everything needed is embedded in the one HTML file; it is intended to work directly as a local file, without a server, account, package manager or internet. The interface has three fictional starting scenes or an empty start. Nothing is sent or saved automatically. Its generated portable passage can be copied or downloaded as plain text; JSON export/import is an optional **deliberate** local handoff. Read files before sharing them: they may contain private text.

The interface is designed to be optional, not a mandatory checklist: the horizon and scene are first, the carrier/action and answer-back second, and authority, timing, evidence and burden are progressive side doors that can be used when load-bearing. Empty data is `UNKNOWN`. It does not compute goodness, a harm score, permission or a validated window; user-declared `OBSERVED` is still **unverified**. Three built-in examples are explicitly fictional; they cannot be cited as real incidents or specialist advice.

## Construction / boundary

- `START_HERE.txt`: under-5 KB standalone machine/human cold entrance; voluntary movement rather than parseable command, separate from HTML. 
- `index.html`: self-contained accessible-labelled HTML, CSS, embedded pure Passage engine plus UI. Source includes a restrictive no-network CSP, no fetch, no analytics, no service worker and no automatic localStorage/sessionStorage. User text flows into textarea `.value` or safe DOM `.textContent`, not inserted into HTML.
- `test.mjs`: 14 deterministic Node built-in tests, including a text-first clip-size/semantic regression without dependencies. Command: `node --test test.mjs` when Node is available. Tests cover unknown/evidence ceiling, three fictional scenes, route/authority/currentness triggers, historical outcome proof, exact schema import/export, hostile input, size guards and source no-network conditions.
- Output is a writer-supplied provisional account, **not** a verifiable event receipt or permission. It is deliberately readable without knowing TRACE glyphs. It links to the formal spine conceptually, not by mutating TRACE.
- No GitHub Pages configuration, deployment, remote API, account integration, public YAC posting, external participant request, VM timer, provider credential or source release is part of this branch.

## One fair practical-advantage test, later and separately authorised

Start from a case that belongs to an actual competent domain owner, not a new fictitious institution invented solely for TRACE. Before showing outcomes, specify a decision that a reader can materially improve; a comparator (careful ordinary conversation and, where available, the strongest relevant domain guidance); time/reader burden; and who independently judges it. Counterbalance source presentation where possible. Score consequential differences, not whether someone recites a framework vocabulary: Did they recognise a worthwhile but inaccessible offer, an actor lacking authority, a weak witness or a correction route arriving too late? Did they also notice unnecessary burden introduced *by Passage*?

**Fail the stronger advantage claim** if ordinary/domain analysis yields the same or better choice faster or with less user effort, or the generated passage looks authoritative without warrant. A smaller educational/portable-compression hypothesis may still be useful, but it needs separate evidence. No outside trial has been run or scheduled.

## How this is different from another forum or ruleset

Passage is not an agent, identity system, ethics engine, admissions control plane or content moderation platform. It produces an inspectable, correctable **provisional narrative**, with side doors to stronger domain methods. It is a disposable reader-entry hypothesis: if it adds no value, discard it without affecting TRACE or ME releases.

**The test is whether somebody can use a small map to make a good possibility reachable — not whether the map looks impressive.**
